# 页面PRD：修改密码页

## 1. 页面信息

| 项目 | 内容 |
| --- | --- |
| 文件序号 | 11 |
| 页面编号 | P08 |
| 页面名称 | 修改密码页（全局弹窗） |
| 所属模块 | 账户维护 |
| 所属功能模块 | 系统PRD 5.8.1「修改密码」；入口来自 5.2「工作台」全局导航 |
| 可访问角色 | 普通用户、管理员（所有已登录用户） |
| 布局容器 | 全局弹窗层（覆盖于问答平台壳层或管理后台壳层之上，见总览 Q4） |
| 依据的领域模型上下文/聚合 | 身份与访问上下文：`UserAccount`（`Credential`）；核心业务行为 `UserAccount.changePassword` |

## 2. 页面定位与目标

所有已登录用户均可通过工作台头像下拉进入，以单独弹窗形式完成本人密码自助修改（PRD 5.8.1）。承载完整表单字段与业务规则，实质为全局弹窗组件，可在任意已登录页面触发。

## 3. 使用角色与权限

- 普通用户与管理员均可使用（PRD 3）。
- 仅能修改本人密码；管理员不代改（PRD 5.8.1）。

## 4. 进入路径与导航关系

- **入口**：问答平台壳层（P02/P03-01）顶栏头像下拉「修改密码」；管理后台壳层内是否保留头像入口见总览 Q4。
- **离开路径**：成功或关闭后回到触发时所在页面；不强制退出登录（PRD 5.8.1）。

## 5. 页面结构

1. **弹窗表单区**：用户名（只读）、原始密码、新密码、确认密码（PRD 5.8.1）。
2. **操作区**：确定提交、关闭/取消。

## 6. 关键组件清单

- 用户名只读展示、原始/新/确认密码输入、提交与关闭操作、校验结果提示

## 7. 页面状态

- 初始态、提交中态、成功态、失败态

## 8. 核心交互流程

1. 用户点击头像下拉「修改密码」，打开弹窗。
2. 填写原始密码、新密码、确认密码，点击确定。
3. 原密码校验通过 → 修改成功，不强制退出；失败 → 提示重新输入。

## 9. 展示的业务数据

- `UserAccount.username`（只读）、`Credential`（通过 `changePassword` / `verifyCredential`）

## 10. 业务规则与约束

- 须输入正确原始密码（PRD 9.8.29）。
- 修改成功不强制退出（PRD 5.8.1）。
- 无重置/找回密码能力（PRD 第6节、领域模型 3.1 不变量6）。

## 11. 异常与边界场景

- 原密码错误、新密码与确认密码不一致。

## 12. 待确认事项

- 管理后台内是否保留入口（Q4）；新密码格式/强度要求 PRD 未说明。
