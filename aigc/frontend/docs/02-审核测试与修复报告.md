## 4. 串联验收（文字走查）

因本环境无浏览器自动化工具，以下为**静态代码级**串联走查（逐跳确认路由/Store/组件调用链路存在且类型/契约一致），非真实点击：

1. **P01 登录**：`LoginShellView` → `LoginPanel` → `useLogin` → `authStore.login()` → Mock 校验账号密码 → 写入 `oara-auth`（token/currentUser）→ 按 `role` 跳转 `/workbench`（user）或 `/workbench`（admin 同样先落到工作台，顶栏显示「管理后台」入口）。链路完整。
2. **P02 → 知识库类来源 → C06 → 关闭**：`AgentChatView` 内 `MessageBubble`→`SourceCitationList`→`open-source` 事件 → `AgentChatView.handleOpenSource` → 打开全局 `AnswerSourceDetailDialog`（C06），关闭后 `v-model` 回落 `false`，回到 P02。链路完整，且 `hasSources` 计算属性保证仅 `done` 状态非空来源才渲染（AGENT-03）。
3. **P03-01 → P03-02（来源→C06）**：`QaHistoryListView` 点击「查看」打开 `QaHistoryDetailDialog`（C01，接收 `record-id`），详情内来源展示逻辑与 C06 一致的 Props 契约。链路完整。
4. **管理员 → 管理后台 → P04/P05/P06/P07-01**：`AdminShellView` 左侧菜单跳转 `AdminUsers`/`AdminAuditLog`/`AdminDashboard`/`AdminQueryLogs`/`AdminKnowledgeBase`，均带 `meta.roles: ['admin']`，`router/guards.ts` 校验非 admin 直接拦截跳转 `/login` 或提示无权限。
5. **P07-02（来源→C06）**：`QueryLogListView` → `QueryLogDetailDialog`（C04）→ 来源点击 → 全局 C06，契约一致。
6. **P09-01 → P09-02**：`KnowledgeBaseListView` → `KnowledgeUploadDialog`，上传校验（类型/大小/重复）在 Mock 层与前端弹窗双重把关；上传后轮询状态由 `解析中→已入库/处理失败` 流转（Mock `scheduleProcessing`）。
7. **P08**：`ChangePasswordDialog` 分别挂载于 `WorkbenchShellView` 与 `AdminShellView` 头像下拉，两壳层入口均存在（非仅一处）。
8. **退出**：顶栏「退出登录」→ `authStore.logout()` → 清空 token/currentUser → 跳转 `/login`。
9. **普通用户权限边界**：路由表中 `/admin/*` 全部 `meta.roles: ['admin']`，普通用户登录后顶栏不渲染「管理后台」入口（模板按 `currentUser.role` 条件渲染），且即使手动改 URL 访问，`beforeEach` 守卫会拦截并重定向——满足「普通用户点来源不得进入管理后台/P09」。

**结论**：以上链路在静态代码层面均已打通，未发现断链。因缺少浏览器工具，未做像素级/交互级最终确认，已在 §7 明确标注为「未做 UI 点击冒烟」。
